# #80 i1 — Trip-level idea shelf: contract and screen in one pass

Q8 = A, so the data contract and the screen land together. Below is what
changed, the decisions the vet findings forced, and what I am handing the walk.

## 1 · The contract

**`packages/core/src/domain/types.ts`**

- `ideaCategory` — the new `do | eat | stay` enum (`types.ts:39`). Its own
  vocabulary, per Q2 = A; the bridge into the DS's five-category language is in
  `packages/ui/src/category.ts`.
- `idea` (`types.ts:73-84`) gains `tripId: z.string()` and
  `category: ideaCategory.default("do")`; `stopId` becomes
  `.nullable().default(null)`.
- `trip` (`types.ts:158`) gains `ideas: z.array(idea).default([])` — the shelf,
  beside `legs`.
- `ideaCreateInput` (`types.ts:322-337`) — `tripId` required (uuid), `stopId`
  nullable defaulting to null, `category` carried.
- `ideaPatchInput` (`types.ts:356-372`) — gains `category` and
  `stopId: z.string().uuid().nullable()` under `.partial()`.

**`packages/core/src/domain/leaf-form.ts`**

- `ideaPatchColumns` (`:248`) is UNCHANGED in behaviour and that is the point:
  only `place` is destructured out, so `stopId` and `category` ride through in
  `...rest` as the real columns they are. The doc comment now says so
  explicitly (`:240-247`), and the tests pin it.
- `ideaDraftInput` (`:200`) now takes a `parent` object
  `{ tripId, stopId?, category? }` instead of a bare `stopId` string — the shelf
  create has no stop in hand, and one object stops the two creates being
  confused at a call site.
- `ideaRestoreInput` (`:290`) carries `tripId`, `stopId` and `category`, so an
  undone delete puts a shelf idea back on the shelf.

**`packages/db/src/schema.ts`**

- `ideaCategory` pgEnum (`:44`).
- `ideas` (`:133-165`): `trip_id` uuid NOT NULL → trips ON DELETE CASCADE,
  `stop_id` nullable, `category` NOT NULL DEFAULT 'do', new
  `index("ideas_trip_idx")`.
- `tripsRelations` gains `ideas: many(ideas)`; `ideasRelations` gains `trip`.

**Migration `packages/db/drizzle/0005_parched_frank_castle.sql`** — generated by
`pnpm db:generate`, then HAND-EDITED at line 3-5: drizzle emitted
`ADD COLUMN "trip_id" uuid NOT NULL`, which fails on a populated table. It is
now add-nullable → `UPDATE … FROM stops JOIN legs` backfill → `SET NOT NULL`,
exactly the design's SQL. The snapshot json is untouched, so the CI drift check
still compares clean.

## 2 · The ownership move (design Gap 1 — the part that is not optional)

`packages/db/src/mutations.ts:69` adds `ownedTripIds(owner)` beside
`ownedLegIds`/`ownedStopIds`, and all five idea write sites re-scope from
`inArray(ideas.stopId, ownedStopIds)` to `inArray(ideas.tripId, ownedTripIds)`:

- `updateIdeaFields` (`:562`), `deleteIdea` (`:569`),
  `promoteIdeaToReservation` (`:590`), and `writeIdeaPin`
  (`packages/db/src/locate.ts:186`).
- `loadIdeas` (`locate.ts:81-87`) and the idea arm of
  `listLocateTargetsForOwner` (`:105-109`) join `ideas → trips` directly and
  drop the stop/leg hops. `locate.ts`'s private `ownedStopIds` copy is gone with
  its last caller.
- `createIdea` (`mutations.ts:466-522`) takes `tripId` + `category` + an
  optional `stopId`, proves the TRIP through the pre-existing `assertOwnedTrip`
  (`:165`), and — when a stop is sent — proves the PAIR through the new
  `assertStopInTrip` (`:373`): the invariant no FK can span the join. sortOrder
  appends within the row's own list (its stop's, or the shelf's).
- `promoteIdeaToReservation` now also refuses an idea with `stopId === null`
  (`mutations.ts:592`): `reservations.stop_id` is NOT NULL, so that promote is a
  constraint violation, not a UX choice. It throws the same "idea not found" the
  handler already answers 404 to.

## Decisions forced by the vet findings

1. **The `POST /api/stops` body (HIGH).** The wireframe's flat
   `{legId, placeName, lat, lng, googlePlaceId, …}` would have been dropped by
   `safeParse`. `doPlanIdea` sends the NESTED `place` that `stopCreateInput`
   actually declares (`TripPlanner.tsx:495-497`), which already carries
   `googlePlaceId` — so `api/stops/route.ts` needed no change at all, and Q7's
   "store the Google id aggressively" is satisfied by sending the whole place.
2. **The shelf card is a NEW component, not `IdeaCard` (HIGH).** `IdeaCard`
   unconditionally renders stars, a note pen, a Book action and `IdeaPlaceLine`;
   the frame's shelf row is a grip, a title, a place line and a pill. Rather
   than five flags on one component I added `ShelfIdeaCard`
   (`DetailCards.tsx:270`). **The per-row distance** the vet asked me to name:
   `ideaShelf` computes it as the nearest LOCATED stop by `haversineMeters` and
   the miles to it, rendered as `"Village Camp Truckee · 1.4 mi"`. The frame's
   `"Truckee, CA · 1.4 mi"` reads as a CITY line, and there is no city column on
   an idea — flagged for the walk below.
3. **`StopBar` is a DS change (HIGH).** It had no `active`/drop props. I added
   them as optional, mirroring `OpenSpan`'s contract; nothing else about the bar
   moved. `packages/ui/src/Gantt.tsx` is therefore in this item's diff even
   though plan.json did not list it.
4. **`FilterChip` gained a warn tone (MED).** It had exactly two looks; the
   amber "No place yet" chip is a third. One optional `tone` prop, tokens only.
5. **The coordless copy (MED).** `ShelfIdeaCard` renders the shipped
   `PICKED_COORDLESS_LABEL` constant, not the frame's abbreviation.
6. **"Change place" (MED) is NOT here.** q7 signed off only "Clear place", and
   both are i2 (#74). What i1 does ship is `onLocate` on a coordless shelf row
   (the #69 entrance), so a shelf idea with no coordinates can still get some.
7. **i3's `coalesce` is not here** — `loadIdeas` is only re-joined to `trips`;
   the search-text change stays i3's.

## Things I decided that the design left open

- **Gesture 3's door.** "Attached idea → back to the shelf" has no drag SOURCE
  in the timeline (an attached idea renders in the stop sheet, not as a shelf
  card). I gave it a menu item — "Move to ideas · → the shelf" on the stop
  sheet's idea `RowMenu` (`StopDetailSheet.tsx:511-518`) — firing the same
  `PATCH { stopId: null }`. If the intended door was a drop target on the rail,
  that is a small follow-up, not a rewrite.
- **The shelf card's title is plain text, not a button.** There is no detail
  surface for an unattached idea to open; a shelf row is a handle.
- **The near-chip label** is `Near {stop.place.name}` verbatim (so
  "Near Village Camp Truckee", where the frame shortens to "Near Truckee").
  Shortening a place name is a guess; the honest label is the stop's own.
- **The seed** (`packages/db/src/seed.ts:124`) now plants three shelf ideas on
  the worked trip, one of each kind, so a fresh `pnpm db:seed` has a rail with
  something real on it.
