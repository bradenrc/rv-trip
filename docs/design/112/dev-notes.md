## How each vet finding was resolved
- **HIGH createTrip** — values now carry the three defaults; route test round-trips POST + PATCH.
- **HIGH reservation edit/undo** — `lodgingKind` in patch schema, mutation patch type,
  draft/patch/restore; restore re-parents onto the segment with its clock.
- **HIGH rigOn gating** — `tripRig` on the page, the bundle, `POST /api/routes` (new `tripId`,
  404 on a foreign trip), `/map` (per-trip hashes) and the dashboard miles. Test: a rigOn:false
  trip with a rig on the account keys `no-rig` in the bundle and the upgrade.
- **HIGH phone client contract** — `reservationRowSchema` reads the segment half + kind;
  `CreateReservationInput` is core's create body. Tests in `api-client.test.ts`.
- **MED segment reservations uneditable** — `ownedReservation` segment arm for PATCH/DELETE;
  web booking rows carry a Delete (undo re-POSTs onto the hop). Phone: no delete affordance (the
  phone wireframe shows none) — deliberate W2 limit on the phone.
- **MED cross-leg hops** — `RouteLeg.outboundHop`, drawn under the same seam as `outboundDrive`;
  Greece acceptance asserts both boundary flights.
- **MED moveStop details** — (a) check-in copy "This flight lands …, but X starts …" / "Check in
  to X on … instead"; (b) reconcile like `updateStopFields`; (c) the stop's campground/lodging row
  whose check-out (check-in) matched moves too. A move that would go backwards or outside the trip
  is refused with the same 409.
- **MED zone abbreviation** — Intl's letters when it has them, else a per-zone std/dst table
  (Athens in May is EEST). Test pins EEST/EET/MDT.
- **MED back to Drive** — refused (409 `segment_has_bookings`, and the web/phone say so) while the
  hop has bookings; otherwise the clock is cleared with the mode.
- **MED "Ordinary car routing."** — HERE is still asked for a truck profile with no dimensions, and
  switching to car would reuse cached `no-rig` truck routes under the same key, so the card copy
  was changed to **"Routes aren't checked against a rig."** (`RIG_CHOICES`). **Design: please
  confirm this copy** — it is the one string not taken from the wireframe.
- **MED ownership proof** — `ownedSegment` (segment ⋈ trips on owner) before the insert,
  `updateSegmentMode` scopes its UPDATE through `ownedTripIds`, 409 before the catch-all 404.
  Tests cover foreign segment create (404, nothing written) and foreign mode switch (404, unchanged).

## Defaults / deviations to check at the walk
- Hop "door to door" shows only for a hop with 2+ bookings (matches all three frames: Costa Rica
  shows it, the single-ferry Greece frame does not). Untimed hops borrow the stop's day; PNW's
  Astoria → Newport reads **Wed Aug 5** (2026-08-05 is a Wednesday; the frame's "Thu" is off).
- Home base on a hop reads the city part ("Boise" from "Boise, ID"); stop names are full ("Westin
  Reserva Conchal", so the move button reads "Check out of Westin Reserva Conchal on 01/23
  instead" — the wireframe's shortened "Conchal" can't be derived).
- On a fly-default trip a drive row carries the mono switch (Q7 B "visible on every hop"); a hop
  card always shows its switch, so a PNW hop that was flown can be switched back.
- Stay form keeps the shipped rule that `Cost $` shows only while cost tracking is on.
- Changing `rigOn` in the web settings dialog persists immediately, but the drives keep the hash
  the page rendered with until the next load. The phone re-reads the bundle after Save.
- Phone: mode glyphs are text (🚐 ✈ ⇄) on the setup cards; the empty-list line now reads "No trips
  yet — start one above." (the old copy sent you to the web).
- Walk FLAGs (from the vet, render-required): Hermes Intl zone conversion and abbreviations
  (`localToInstant` / `instantToLocal` / zone chips on the phone); the Timeline fly/ferry click →
  Route scroll + form open; the RN Modal sheets (⋯ action sheet, Add flight, Add stay, Trip
  defaults) on iOS and Android.
