### Change log (vet MED: `again` had to land in all its places)

- `mutations.ts:269`: `LOGGED_FIELDS` is now the single list both logger loops read. It includes `again`, and every `before` select reads `again`.
- `packages/ui/src/change-byline.ts`: the verb is `again → "marked"`. The byline carries no value and the answer can be either Again or Once, so the verb names the act. `changeValueLabel` maps true to "again" and false to "once was enough". This copy is derived because the design didn't specify it.

### Write-through (Q7 B)

- **Core decision.** `packages/core/src/domain/been-write-through.ts:125` is `beenWriteThrough(thing, library)`, which returns skip, update or create. Supporting pieces:
  - `isJournalWorthy` (:70) decides whether a thing writes through.
  - Matching uses `isAlreadySaved`.
  - A reservation is name-only.
  - Travel-category reservations are skipped.
  - An idea or stop with no place is skipped.
- **Type mapping (vet MED).** It's pinned both ways:
  - Idea category to save type, by `saveTypeOfIdeaCategory` (:84): eat→dining, stay→lodging, do→activity. A stop maps to `other`.
  - The reverse, by `ideaCategoryOfSaveType` (now exported from `nearby-saves.ts`).
- **DB writer.** `packages/db/src/mutations.ts:2006` is `writeThroughBeen(owner, target, deps)`. It is called from:
  - `updateIdeaFields` (:1328), `updateStopFields` (:672) and `updateReservationFields` (:1093), but only when the patch names status, rating, again or notes.
  - `createIdea` (:1231), when the new idea is journal-worthy.
- **Destination (vet HIGH).** `SaveDeps.resolveAt` (:1593) lets a reservation's save resolve its destination at the stop's point while its own lat/lng stay null (rule 4). On the update path, a matched save with no destination gets one resolved.
- **Resolver threading.** The ideas, ideas/[id], stops/[id] and reservations/[id] handlers pass `destinationResolver()`, a new helper in `apps/web/src/lib/places.ts`.
- **Update path.** A match is graduated in place:
  - Status becomes been, `source` is cleared, and `trip_id` is set.
  - The thing's rating, again and note override the save's only when the thing has its own. A thing with no ★ never blanks the save's.
  - The change is logged as a save change, so the byline names the actor.
- **Never deletes.** An un-check leaves the Been save in place.
- **Never fails the write it follows.** A write-through fault is logged with `console.error` and swallowed. Otherwise the phone's queue would retry a PATCH that has already landed.
- **Did-it anchor (vet HIGH).** The Did-it POST carries `areaLabel`. The write-through then creates the save with anchor `area` and that label, so a note with a fix lands as area "Playa Flamingo", not as a pin. This is covered by a test.

### Idempotent Did-it POST

## Decisions and defaults to check

- **Floating stops (vet MED).** They come after the scheduled ones, in route order (legs by sortOrder, then stops). A stop with its own ★ or Again counts toward the "in the journal" tally, since "rate a stop … to start its journal". The Westin stop in the acceptance fixture is unrated, so the 4/3/1/1 tally is unaffected.
- **"Around the trip"** uses the same Entry predicate as everything else: done, rated, or with an again answer. "Didn't get to" is every non-entry idea, whether on a stop or on the shelf. A Travel-category reservation attached to a stop goes to the Travel fold.
- **Card fallback when a save has no destination.** A save without a destination (the keyless stub resolves nothing) is measured from its own point, and its card is named after the nearest stop. Without this, every write-through save on a keyless walk would be invisible. This widens the design's "destination point" rule.
- **Row order inside a card.** ★ descending, then Stay/Eat/Do order, then name. This reproduces the wireframe's South Beach above Local Ocean, both ★5.
- **Toast position.** The journal toasts reuse the shipped capture toast layer at the top of the tabs. The wireframe drew them floating at the bottom of the stop screen.
- **Journal sheet Skip link.** It appears only for a check-off. The reservation pill's sheet has no done badge and no Skip; dismissing it closes it.
- **Web CTA color.** The "Add" button on the web uses `bg-rv-green text-rv-navy`, not the wireframe's green-cta, because the repo's colour sweep (`nightfall-tokens.test.ts`) forbids `bg-rv-green-cta` call sites. The web note placeholder uses `rv-ink-faded` for the same reason (ink-subtle is not allowed on text).
- **Web test suite runs keyless.** `apps/web/src/test/setup.ts` now deletes `GOOGLE_API_KEY`. Three more handlers call the resolver now, and a laptop `.env` key would otherwise geocode against real Google during the suite. My first full web run happened before this guard, so a handful of real geocode calls may have been billed then.
- **Reservation undo loses `again`.** Out of scope: `reservationCreateInput` doesn't carry `again`, so an undone reservation DELETE re-POSTs without it.
- **Local and walk database.** I did not run `pnpm db:push` or migrate against the shared dev database. The walk environment needs migration `0004_w3_journal` applied and a re-seed so the coast saves carry `again: true`.
